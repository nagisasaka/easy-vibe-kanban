<Steps>
<Step title="Install OpenAI Codex">
  ```bash
  npm install --global @openai/codex
  ```

  Vibe Kanban launches the `codex app-server` command from your PATH. Keep
  the CLI updated independently; Vibe Kanban does not bundle or pin a Codex
  runtime version.
</Step>

<Step title="Follow the login instructions">
  Complete the authentication flow as prompted. Follow the authentication instructions from the [OpenAI help centre](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan) to use Codex with your ChatGPT plan.

  Alternatively, Codex can be used via the OpenAI API by setting the `OPENAI_API_KEY` environment variable. For more details, see the [OpenAI documentation](https://developers.openai.com/codex/pricing/#use-an-openai-api-key)
</Step>

<Step title="Start Vibe Kanban">
  Once authenticated, launch Vibe Kanban:

  ```bash
  npx easy-vibe-kanban
  ```

  You can now select OpenAI Codex when creating task attempts.
</Step>
</Steps>

## Custom Configuration Directory

By default, Codex stores its configuration and session data in `~/.codex`. If you have configured a custom location using the `CODEX_HOME` environment variable, Vibe Kanban will automatically detect and use that location.

```bash
# Example: Using a project-specific Codex configuration
export CODEX_HOME=/path/to/custom/codex
npx easy-vibe-kanban
```

This is useful for:
- Project-specific Codex profiles
- Separating work and personal configurations
- Custom automation setups

## Reasoning effort

Leave the EVK reasoning override unset to use the configuration resolved by your
Codex app-server. For example, your Codex `config.toml` can contain:

```toml
model = "gpt-6-astra"
model_reasoning_effort = "max"
```

Use an effort supported by the selected model and installed Codex version. EVK
uses Codex's model list for available choices. An explicit EVK reasoning choice
overrides the inherited configuration. New sessions and resumed sessions retain
the reasoning effort returned by Codex when EVK selects Code or Plan mode; mode
selection must not reset an inherited value to `null`.

For OpenWiki Bootstrap, start a new run after changing the configuration so each
fresh Generate, Review and Refine session resolves the new setting. Configuration
edits do not retroactively change an already-running phase. Resumed conversations
can also retain their saved settings; use an explicit EVK override when you need
to change an existing conversation.

When diagnosing unexpected effort, compare `thread/start` or `thread/resume`'s
`reasoningEffort` with the subsequent `thread/settings/updated` notification in
Native Audit. A value that changes from `xhigh` to `null` when the first turn
starts is not successful configuration inheritance. `null` means no explicit
effort, not proof that the model is doing no reasoning.
